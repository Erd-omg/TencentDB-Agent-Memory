# 云主机迁移 · 故障复盘与反模式

> 从真实迁移事故中沉淀的踩坑清单。遇到迁移失败先查本 skill 再动手，避免重复踩坑。

## 1. 反模式清单
| 反模式 | 现象 | 根因 | 处理 |
|---|---|---|---|
| 断点续传丢失增量 | 增量迁移后目标端数据不一致 | 续传未记录偏移量，重复拉取覆盖 | 迁移任务记录 checkpoint，续传前比对偏移量 |
| 迁移前未预检 | 目标端空间/网络不满足导致中途失败 | 跳过 precheck 直接 migrate | 强制 precheck，不通过禁止启动 |
| 停机窗口无评估 | 业务中断超预期 | 未评估全量+增量耗时 | 迁移前必须输出停机窗口评估 |
| 回滚不完整 | 回滚后目标端残留脏数据 | 回滚未清理已写入目标 | 回滚步骤必须幂等且可重放 |
| 未做 VSS/快照 兼容 | Windows 主机权限丢失/卷快照失败 | 忽略 NTFS ACL 与 VSS provider | 迁移 Windows 虚机前先做快照/ACL 兼容处理 |

## 2. 典型故障与根因
- **P1 迁移卡在 verifying**：目标端校验超时 —— 增大验证超时并对大文件做抽样校验。
- **P2 迁移失败但状态机留在 migrating**：状态机未处理异常退出 —— 加超时熔断 + 失败态持久化。
- **P3 全量迁移后磁盘暴增**：未做快照去重 —— 迁移前评估目标端冗余空间。

## 3. 处理清单（遇到失败时）
1. 从日志按 task_id 拉全链路（source -> adapter -> target）。
2. 定位失败阶段（precheck/migrating/verifying/rollback）。
3. 对照上表反模式匹配根因。
4. 执行对应处理；修复后先跑 dry-run 再正式迁移。
5. 复盘结论回流：若发现新模式，用 skill_patch 补充本 skill 或沉淀新 skill。
