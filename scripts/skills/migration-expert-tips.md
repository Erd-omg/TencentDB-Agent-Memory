# 云主机迁移 · 专家经验与最佳实践

> 由「迁移专家」agent 沉淀的团队级迁移经验资产。规划一次迁移前先检索本 skill，
> 覆盖批量迁移编排、停机窗口评估、风险清单与迁移验收四个核心环节。

## 1. 批量迁移规划
- 迁移前按「源端风险 × 目标端风险」四象限给主机分级，低风险先迁、高风险后迁并单独评估。
- 批量任务用有向无环图(DAG)编排依赖：先数据层(DB)后应用层，避免目标端依赖缺失。
- 每个迁移任务必须带 `task_id` 贯穿 source -> adapter -> target，中途失败可定位到段。

## 2. 停机窗口评估
- 停机窗口 = 全量传输耗时 + 增量同步窗口 + 校验耗时 + 安全缓冲（至少 20%）。
- 传输耗时按源端磁盘已用量/带宽实测值估算，禁止按理论峰值。
- 增量窗口：若业务写入速率超过增量拉取速率，需回退「先停写再全量」。

## 3. 迁移风险清单
| 风险 | 前置检查 | 规避 |
|---|---|---|
| 目标端磁盘不足 | 校验目标端剩余空间 ≥ 源端已用 × 1.5 | 预留扩容开关 |
| 带宽受限导致超时 | 迁移前跑带宽探针 | 限速+断点续传，失败可续 |
| 目标端架构差异 | 对比 OS/磁盘/网络栈 | 差异项先做兼容性测试 |
| 源端有未落盘写入 | 检查源端 IO 队列 | 迁移前 flush+quiesce |

## 4. 迁移验收
- 验收五连：数据一致性(抽样比对)、服务可达性(健康检查)、权限正确性、回滚演练、性能达标。
- 未通过验收不解除源端只读；验收通过后保留回滚窗口至少 72h。
